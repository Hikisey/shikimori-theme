# AGENTS.md — памятка для правок hikisey theme

короткая навигация для ai-ассистентов (и для себя в будущем). подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), инструкция для пользователей — в [README.md](README.md).

## что где лежит

исходники — модули в `src/`, порядок каскада задаёт `src/manifest.txt` (сверху вниз). `css/part_NN.css` — собранные части для `@import`, руками их не правят.

| слой | модули | что внутри |
|---|---|---|
| токены | `tokens/palette.css`, `tokens/components.css` | палитра (`ПАЛИТРА ТЕМЫ`), производные оттенки и формулы `@supports (color: rgb(from red r g b))`; токены компонентов `--plate-*`, `--heading-*`, `--btn-*`, `--arrow-*`, `--card-*`, `--tip-*`, `--tab-*`, `--field-*`, `--ease-*` |
| база | `base/fonts.css`, `base/animations.css`, `base/base.css`, `base/colors.css` | шрифты, все `@keyframes`, ссылки/текст/таблицы/скроллбары, цветовые классы bb-кодов |
| каркас | `layout/header.css`, `layout/page.css`, `layout/footer.css` | верхняя панель; html/body, обои, `.l-page`, сетки `.cc`/`.c-column`; подвал и `--theme-version` |
| компоненты | `components/*.css` | `badges`, `carousels`, `tooltips`, `headings`, `users`, `buttons`, `stats`, `tabs` (в т. ч. `.b-options-floated`, `use-tabs`), `plates`, `cards` (`.b-catalog_entry`), `editor` (комментарии, редактор, спойлеры), `modals`, `forms` (поля, select, мультиселект `.c-ms`, галочки) |
| страницы | `pages/*.css` | `anime` (страница аниме/манги/персонажа, кадры и видео, плеер), `lists`, `clubs`, `settings`, `catalog`, `profile` (шапка, баннер, история, статистика), `messages`, `contests`, `forum`, `achievements`, `dashboard` |
| наборы | `kits/about-kits.css`, `kits/custom-posters.css` | наборы «О себе» (не удалять) и свои постеры |
| поздние | `overrides/late.css` | правила, которые обязаны идти после страниц (см. ниже) |

- **телефон рядом с модулем.** в конце каждого модуля — раздел `/* ----- телефон и узкие экраны ----- */` с его правилами для ширины ≤1023 и сенсорных экранов. редкие телефонные правила стоят в основной части модуля внутри своего `@media` — значит, их нельзя опускать ниже соседей (порядок важен).
- **`overrides/late.css`.** правило перебивает правило из модуля, который в манифесте стоит позже, при том же весе селектора, — поэтому оно не может жить «дома». у каждого помечено `/* из <модуль> */`. сейчас их 450 (было 507; 60 вернулись домой с повтором первого класса `.x.x`, 16 удалены вместе со старым видеоплеером). около 240 не совпали ни с одним элементом сохранённых страниц, но их классы есть у шикимори — не удалять без проверки на живом сайте.
- **токены компонентов.** новую плашку, заголовок, кнопку, стрелку ленты или карточку пишите через токены из `tokens/components.css` (`background: var(--plate-bg)`, `border-radius: var(--plate-radius)`, `transition: transform var(--ease-fast)`…), а не числами. новый общий вид — новый токен там же. в `-webkit-backdrop-filter` токены и `var()` нельзя: только фиксированное значение. стрелки новой ленты — допишите её прокручиваемый блок в `:is(...)` в `components/carousels.css`.
- **порядок внутри модуля и между модулями — это каскад.** новые правила добавляйте в конец своего модуля (или его телефонного раздела). переставлять правила и модули можно только с проверкой (см. «проверки»).
- **искать по селектору:** `rg -n 'b-catalog_entry' src/` — модулей много, но правило всегда в одном месте.
- `site.css` — то, что пользователь вставляет в «Внешний вид сайта» (импорты с тегом + палитра). `README.md` — для пользователей. `docs/ARCHITECTURE.md` — полная карта, фильтр шикимори, история версий.

## сборка и проверки

- **сборка:** `python3 tools/build.py` — склеивает модули по `src/manifest.txt` и режет на `css/part_NN.css` по ≤ 80 000 байт (только между правилами; предел скрипта — 100 КБ, больше шикимори не импортирует). в конце печатает строки `@import`. `--version X.Y.Z` заодно ставит версию в подвал (`layout/footer.css`).
- **быстрая проверка — по умолчанию для любой мелкой правки:** `python3 tools/quick_check.py --page <сохранённая страница шикимори> [--phone]`. собирает во временную папку (`css/` не трогает), гоняет эмуляцию фильтра шикимори (`tools/shiki_compile.py`: не пропала ли скобка/правило), проверку ссылок после camo (`tools/shiki_url_check.py`), жёсткие правила (behavior, `@view-transition`, обратные слэши, размер частей), считает `:hover` вне медиазапроса и делает скриншот страницы с темой (`tools/shot.js`, нужен node + playwright-core + chrome). без `--page` — только проверки. у автора сохранённые страницы лежат в `theme-opt/check/` (`entry.html` — страница манги, `profile.html` — профиль).
- **полная регрессия — только перед релизом:** вычисленные стили всех элементов (обычное состояние и hover/focus/active) на ~30 сохранённых страницах пк и ~15 телефонных плюс ширины 820 и 1100, сравнение с прошлым тегом и попиксельные скриншоты. инструменты лежат у автора вне репозитория.

## палитра

- исходные значения: `src/tokens/palette.css`, первый блок, внутри `@media screen and (min-width: 1px) { html:root { … } }`.
- те же переменные с пояснениями повторяются в `site.css` — это то, что видит пользователь.
- 4 группы: `--accent`/`--link`, фон (`--bg-*`, `--profile-banner*`), стекло (`--glass`, `--glass-light`, `--glass-blur`), текст (`--text`, `--text-2`, `--text-3`, `--text-strong`); отдельно оценки и шкалы.
- цвет — rgb-тройка без `rgb()`: `--accent: 232, 108, 108;`, используется как `rgba(var(--accent), .5)`.
- старые имена (`--bright-color`, `--block-color`, `--page-bg`…) поддерживаются через `var(--old, default)`.

### как добавить или поменять цвет

1. базовый цвет — новая переменная в палитре `tokens/palette.css` (первый блок) и такая же строка с комментарием в `site.css`; в README — строка таблицы палитры.
2. производный оттенок — две записи: число в блоке `Производные оттенки` и формула в `@supports`-блоке (оба в `tokens/palette.css`), например `rgb(from rgb(var(--accent)) calc(r * 178 / 232) calc(g * 58 / 108) calc(b * 64 / 108))`. при значениях по умолчанию формула должна давать ровно то же число.
3. прозрачность — через `color-mix(in srgb, var(--x) 55%, transparent)` или `rgba(var(--x), .55)`.
4. в правилах используйте переменную, а не число. числами намеренно оставлены статусы, ачивки, bb-коды, подсветка кода, бренды, цвета наборов «О себе».
5. пользовательские переопределения всегда в `@media … { html:root { … } }`, иначе шикимори применит их только на ширине ≥1024.

## выпуск релиза

1. правки — в модулях `src/`; `css/part_NN.css` руками не править.
2. сборка: `python3 tools/build.py --version X.Y.Z` (подвал «hikisey theme vX.Y.Z»). части ≤ 80 КБ: 4mob на 231–234 КБ шикимори не импортировал (v1.2.21–22), подробности — в docs/ARCHITECTURE.md, «почему тема разбита на части».
3. проверки: `tools/quick_check.py` без ошибок + полная регрессия (см. выше).
4. в `site.css` и `README.md` заменить старый тег на новый во всех `@import`; если число частей изменилось — заменить весь список строк.
5. commit → push в `main` → тег `vX.Y.Z` → GitHub release с описанием на русском.
6. проверить, что части 1–4 на `raw.githubusercontent.com/Hikisey/shikimori-theme/vX.Y.Z/css/part_NN.css`, части 5–8 на `cdn.jsdelivr.net/gh/Hikisey/shikimori-theme@vX.Y.Z/css/part_NN.css` (запросить — это и прогрев кеша jsDelivr) и `site.css` отдают 200 и совпадают с репозиторием.

почему 5–8 через jsDelivr: GitHub raw, похоже, ограничивает сервер шикимори после 4–6 файлов подряд — части 5–8 с raw стабильно «не удавалось импортировать» (v1.3.3), с jsDelivr подключаются. подробнее — docs/ARCHITECTURE.md.

почему теги: шикимори качает каждый `@import` на своём сервере и кеширует по адресу на 8 часов (неудачу тоже). новый тег — новый адрес, он подхватывается сразу и не меняется потом. `main` — только для разработки. правки только документации идут в `main` без нового тега. опубликованные теги не переносить (это force-push).

## жёсткие правила

- **без минификации.** файлы остаются читаемыми: в v1.2.9 сжатие склеило `url("…")}` и camo-прокси съел следующие правила.
- **`;` перед `}` после `url()`** всегда: `background: url("…");}`. иначе регулярка ссылок шикимори захватит `)` и `}`.
- **нет слова `behavior`** нигде, даже в комментариях и внутри `scroll-behavior`: шикимори вырезает его (а также eval, cookie, window, parent, this, script, expression, javascript, moz-binding, charset, `<`).
- **нет `@view-transition`.**
- **нет обратных слэшей** вне строк `content: "…"`: `\` + буква/цифра вырезается. иконки — только в `content`.
- **data uri — только base64** `data:image/(svg+xml|png|jpeg|jpg|gif);base64,…`; остальное вырезается.
- **`:hover` — только внутри `@media (hover: hover) and (pointer: fine)`**; на сенсорах — отклик через `:active`.
- **правки только для телефона** — внутри `@media screen and (max-width: 767px)`; пк не трогать.
- **`-webkit-backdrop-filter` — фиксированные значения, без `var()`**: Safari молча игнорирует его с `var()`. порядок: сначала `backdrop-filter: blur(var(--glass-blur));`, последней строкой `-webkit-backdrop-filter: blur(5px);`.
- **наборы «О себе» не удалять** (спойлеры, вкладки, плееры, ссылки) — ими пользуются в профилях.
- **без символа `@` в ссылках** на картинки — шикимори его вырезает.
- **наведение не должно сдвигать сам элемент под курсором.** если `:hover` поднимает элемент (`translateY`), у нижнего края курсор выпадает из него, наведение снимается, элемент опускается — и так по кругу (мигает курсор, пропадают подсказки). варианты: поднимать содержимое внутри (`a:hover::before`), увеличивать от нижнего края (`transform-origin: 50% 100%` + `scale`), или добавить невидимую полоску под поднятым элементом (`:hover::after { position: absolute; top: 100%; height: 10px }`, не работает при `overflow: hidden`). подсказки `.tipsy` — с `pointer-events: none`.
- **название темы — строчными: «hikisey theme»**; подпись в подвале «hikisey theme vX.Y.Z».
- стиль оформления: мягкое стекло, без js (скрипты в стилях невозможны).

## ловушки шикимори кратко

| что | последствие |
|---|---|
| css без `@media` | оборачивается в `@media only screen and (min-width: 1024px)` |
| `@import` | качается сервером шикимори, таймаут 5 с, кеш 8 ч, ошибка = пустой файл; с GitHub raw подряд проходят только ~4–6 файлов, поэтому части 5–8 — с jsDelivr |
| комментарии | вырезаются при компиляции |
| ссылки `https://` и `//` | обе переписываются на camo-прокси шикимори (кроме доменов шикимори) |
